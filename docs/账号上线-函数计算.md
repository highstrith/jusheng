# 账号上线：GitHub Pages + 阿里云函数计算 + OSS

站点仍是 GitHub Pages 的静态页，账号／订单／观影三个接口跑在阿里云函数计算（FC），
数据存在 OSS 桶 `jusheng-accounts`。前端通过 `review-config.js` 里的
`window.FRAMEPICK_ACCOUNT_API` 指向函数地址。

```
浏览器 https://highstrith.github.io/jusheng/
   │  fetch + Authorization: Bearer <token>
   ▼
函数计算 Web 函数  https://<函数域名>/api/framepick/...
   │  OSS V1 签名（内网 endpoint）
   ▼
OSS  jusheng-accounts/framepick/{accounts,orders,viewing}/*.json
```

## 为什么是这套

- OSS 只能存文件，注册、登录、会话校验必须有跑代码的地方，所以桶和服务都要。
- 函数计算 Web 函数自带 HTTPS 域名，不用买域名、不用备案，闲置时基本不花钱。
- 跨站 Cookie 会被 Safari／微信按第三方 Cookie 丢掉，所以登录态改用
  `Authorization: Bearer`（`localStorage` 里的 `framepick:session:v1`），Cookie 只在本机预览时生效。
- 三个模块都是「整份 JSON 读改写 + 进程内缓存」，多实例会互相覆盖，
  **函数的最大实例数必须固定为 1**。

## 一、先在控制台给桶授权（否则连本地都传不上去）

当前管 OSS 的 RAM 子账号对 `jusheng-accounts` 没有权限，`ossutil ls` 直接 403。
在 RAM 控制台给它加一条只作用于该桶的策略：

```json
{
  "Version": "1",
  "Statement": [
    { "Effect": "Allow", "Action": ["oss:ListObjects", "oss:GetObject", "oss:PutObject", "oss:DeleteObject"], "Resource": ["acs:oss:*:*:jusheng-accounts", "acs:oss:*:*:jusheng-accounts/*"] }
  ]
}
```

`DeleteObject` 现在就是为了能删测试对象；线上服务本身只做读和写。

## 二、给函数建一个 RAM 角色

1. 访问控制 → 角色 → 创建角色 → 选「阿里云服务」→ 云服务选「函数计算」。
2. 角色名 `framepick-api`（代码默认从实例元数据读这个角色的 STS 临时凭据）。
3. 给它挂和第 1 步一样的桶权限策略。

这样函数里不需要任何常驻 AK，凭据由 FC 注入。

## 三、打包并部署函数

```sh
./scripts/pack-fc.sh          # 生成 dist/framepick-api.zip
```

控制台：函数计算 3.0 → 创建函数 → **Web 函数**。

| 项 | 值 |
| --- | --- |
| 运行环境 | Node.js 20（或 18／22，代码只用标准库） |
| 代码 | 上传 `dist/framepick-api.zip` |
| 启动命令 | `node framepick-api.cjs` |
| 监听端口 | 9000 |
| 实例数 | 最小 0，**最大 1** |
| 内存 | 512 MB 足够 |
| 超时 | 30 秒 |
| 角色 | `framepick-api` |

环境变量：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `FRAMEPICK_STORE` | `oss` | 不设则退化为 `/tmp` 文件存储（重启即丢，仅演练用） |
| `OSS_BUCKET` | `jusheng-accounts` | |
| `OSS_ENDPOINT` | `https://oss-cn-hangzhou-internal.aliyuncs.com` | 必须和桶同地域；跨地域改成公网 endpoint |
| `OSS_PREFIX` | `framepick` | 实际对象在 `framepick/<模块>/` 下 |
| `FRAMEPICK_ALLOWED_ORIGIN` | `https://highstrith.github.io` | CORS 只放这一个来源 |
| `FRAMEPICK_TRUST_PROXY` | `1` | 限流按 `x-forwarded-for` 取真实客户端 IP |

部署后在控制台点开函数域名，访问 `/healthz`，应返回：

```json
{ "ok": true, "store": "oss", "origin": "https://highstrith.github.io" }
```

## 四、把地址填进站点

编辑仓库根目录的 `review-config.js`（构建时原样发布，改完推 main 即生效）：

```js
window.FRAMEPICK_ACCOUNT_API = 'https://<你的函数域名>';
```

然后 `./scripts/ship.sh`。线上验证：

1. 打开 https://highstrith.github.io/jusheng/ → 右上角账号入口不再是「尚未部署」。
2. 注册一个新账号 → 刷新页面 → 仍是登录态（Bearer 生效，不依赖 Cookie）。
3. 手机 Safari／微信内置浏览器各试一次，这里最容易暴露第三方 Cookie 问题。
4. 打开「我的」→ 观影记录能同步；演示下单能走通。
5. 回 OSS 控制台确认出现 `framepick/accounts/accounts.json` 等对象。

## 五、这次没上线的部分

- `reviews`（共享评价）与 `creators`（创作者工作台）仍走本地文件，线上保持
  「未配置共享评价服务」的现状。它们要上线得先解决访客身份跨站的问题，另开一轮。
- 评价数据继续留在 `~/.framepick/reviews`，不受本次改动影响。

## 排错

| 现象 | 原因 |
| --- | --- |
| `/healthz` 502 | 启动命令或端口不对；看 FC 日志 |
| 注册 500，日志里 `AccessDenied` | 角色没挂桶权限，或 bucket 名写错 |
| 注册 403 `Forbidden origin` | `FRAMEPICK_ALLOWED_ORIGIN` 与实际站点来源不一致 |
| 刷新后掉登录 | 前端还在用旧版 `framepick-accounts.js`（缓存），确认 `?v=` 已更新 |
| 数据偶发回退 | 函数实例数不是 1，两个实例各写各的 |
| 本地 `curl` 报 ECONNREFUSED | 机器上设了 `HTTP_PROXY=127.0.0.1:7897` 但代理没开，加 `--noproxy '*'` |

## 本地演练

```sh
FRAMEPICK_STORE=file FRAMEPICK_TRUST_PROXY=1 PORT=9000 node server/framepick-api.cjs
curl --noproxy '*' http://127.0.0.1:9000/healthz
```
