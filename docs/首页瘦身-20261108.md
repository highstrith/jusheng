# 首页瘦身与结构重组（2026-11-08）

## 起因

首页单文件 154KB、内联 55 张作品卡，既当编辑首页又当完整片库，两个重心互相打架。
同时发现三处片数写死在代码里（分享卡片写 42 部、无 JS 兜底 32 部、实际 55 部），
每轮自动上新都会让偏差更大。

## 做了什么

### 1. 首页只铺一屏（生成器口径改了，不是手改 HTML）

`scripts/build-framepick-library.mjs` 现在只往 `#filmGrid` 里写 9 张卡：

- 取**最近收录**（`intakeDate` 倒序，同日保持片库顺序）；
- **让开本周推荐已经展示过的作品**，避免同一批封面连排两次；
- 首页作品总数由 `data-total` 带着走，卡片数不再等于片库总数。

首页 `#entries` 区块改名为「最近收录」，搜索框改成 `GET library.html?q=` 的表单，
筛选、排序、分页、搜索全部归 `library.html`。原筛选控件留在 DOM 里但 `hidden`——
引擎（`framepick.js`）靠这些控件初始化，直接删会连锁报错。

### 2. 栅格外作品也能开详情

本周推荐和主推里的片可能不在首页九张卡里，而详情弹窗按 id 从栅格卡片取数，
缺了就打不开。分两层兜：

1. **常用的一小撮**由生成器内联：`<script id="detailExtras">window.FRAMEPICK_DETAIL_EXTRAS = [...];</script>`
   （主推 + 本周推荐 5 部，约 4KB）；
2. **其余全量**按需取：`framepick.js` 的 `openFilm()` 查不到时注入 `films-data.js`
   再打开，所以分享链接 `?film=<任意作品>` 仍然有效，而首页平时不为它付体积。

`framepick.js` 增加 `lookupFilm(id)`（栅格 → 内联 → 按需表），收藏恢复、深链、
弹窗取数统一走它；`films-data.js` 补了 `episode` / `volume` / `relation` 三个字段，
否则按需解析出来的详情会缺集数与体量。

### 3. 数字只有一个来源

生成器统一写入：`data-total`、`<span data-film-total>`、`og:description`、
`#resultCount`、`library.html` 的 `#libMeta`。以后不会再出现 42/32/55 三个数。

### 4. 可读性与加载

- 移动端字号下限：卡片元信息 10–11px → 11–12px（桌面不动）；
- 三张页面加图片域名 `preconnect`（线上图在杭州 OSS）；
- 新增 `robots.txt`、`sitemap.xml`，并同步 `build-site.sh` 的两份白名单。

> 坑：`build-site.sh` 先按白名单复制、再清理「产物清单外」的文件，
> 只加复制不加清理名单，两个新文件会被当场删掉（本地跑一次就会看到
> `陈旧文件清理 2 个`）。两份名单必须一起改。

### 5. 收藏与「我的」入口

首页只剩九部之后，两件事被暴露出来：

1. `site-mode.js` 的 ranking 模式把 `#meEntry`（我的）整块隐藏了 —— 不是只在手机隐藏，
   桌面也没有，`me.html`（观看历史 + 账号）只能靠地址进；
2. `#savedToggle`（我的收藏）是在栅格里筛的，而收藏存在浏览器里、可能指向九部之外的作品，
   一点就落到「暂时没有匹配的作品」，等于死链。

改法：

- 恢复 `#meEntry`（`framepick.css` 的 ranking 隐藏清单里删掉它），保留账号入口的开关逻辑；
- `library.html` 支持 `?saved=1`：读 `framepick:saved:v1` 过滤整份作品表，标题变「我的收藏」，
  空态说清楚「这台浏览器还没有收藏」；
- 首页筛选到收藏且九部里没有时，底部的去片库入口改成「去片库看我的收藏（N 部）」→ `library.html?saved=1`；
- `me.html` 的「我的收藏」链接改到这个视图。

手机顶栏要塞四组（品牌 / 导航 / 我的 / 收藏），加回「我的」后在 390px 折成两行。
只收紧间距与品牌字号（≤430px 再降一档），不删入口：390 单行，320 第二行「我的 + 收藏」靠右收齐。

### 6. `seed` 不能再读首页卡片

`scripts/framepick-library-cli.mjs seed` 原来解析 `index.html` 的卡片来初始化作品库。
首页只剩九部之后，跑一次 `seed` 会把整份片库导成九部（Node 集成测试
「builder reproduces the shipped catalogue byte for byte」直接抓到了）。
改成优先读 `films-data.js`（全量、字段齐全），没有这个文件才退回解析卡片。
同样的问题也在 `serve.js` 的 `readFilmIds()`（评论与离站接口的合法作品名单）：
不修的话本地预览里给九部之外的作品写评价会 404，一并改成读全量表。

### 7. 测试跟着改

旧测试假设「首页有筛选、分页、搜索框、每页 12 部」。改为：

- 筛选/排序/分页/搜索的断言迁到 `library.html`；
- 首页只断言「9 部、无分页、有去片库的入口、搜索能交棒」；
- 评分依据（编辑/站内）筛选已无可见入口，测试改为直接驱动隐藏控件的状态并触发事件，
  地址参数 `?scoreBasis=community&rating=8` 仍然生效；
- 评论/离站测试的服务端 fixture 里作品白名单原来写死 `xianggu/jinhaitang/yanran`，
  首页改铺「最近收录」后新片子的离站点击被当成未知作品丢掉 → 改成从 `films-data.js` 读全量 id；
- 评论测试改成**每个用例一套空数据库**（各起一个 node 服务）。原来整类共用一个数据目录，
  评价与离站计数会在用例之间累计，`2 人评分` 变成 `3 人评分`。
  顺带从 90 秒降到 24 秒（不再有相互等待超时）；
- 详情图断言改成「取页面第一部 + 大图优先单独一条（扫描 `img/*-1280w.webp`）」，
  不再假设首页有 `pinzi`；新增 `library.html?saved=1` 的收藏视图用例；
- Node 集成测试的「新片上架」用例改为看 `data-total` 与 `films-data.js`，
  首页卡片数只断言「保持一屏」，不再等于总数。

### 8. 首屏主推从写死改成可轮换

原来 `<article class="feature">` 是手写死的一整块：封面、标题、那两行编辑文案、角标，
全在 `index.html` 里。生成器只写 `#filmGrid`，`feature` 在代码里出现 0 次 —— 也就是
55 部片进进出出，首屏永远是同一张，而且没人记得手动改。

现在这块也由生成器写，选谁按优先级：

1. `data/feature-film.json` 里钉的 id（编辑手选）；
2. 本周推荐第一部（`data/weekly-picks.json` 最后一周按顺序取），**每周一随榜单自动换**；
3. 兜底：最近收录第一部。

```sh
node scripts/build-framepick-library.mjs --feature xianggu   # 钉住某部（同时重建页面）
node scripts/build-framepick-library.mjs --feature auto      # 交回本周推荐
```

角标跟着来源走：自动选中写「本周主推」，手选写「编辑选片」，兜底写「最新收录」——
不撒谎，读者也知道为什么每周会变。

**文案不另写**：右栏那行说明取简介第一句（超过 46 字截断加省略号），没有简介才退回
「题材 · 来源」。题材已经在标签行，不重复写第二遍。要更讲究的话，以后可以在片目里
加一个 `featureLine` 字段，生成器优先用它 —— 但那样每换一部都得有人写一句。

**首名只出现一次**：主推就是「本周推荐第一名」时，榜单里不再重复列它 ——
`scripts/build-weekly-picks.mjs` 用同一个 `scripts/lib/feature.mjs` 算出主推，
把那一部从列表里摘掉，卡片名次从 02 接着数（不是重新从 01 数）。
说明文案也跟着变成「首推《X》见页首，其余 4 部按首发日期排列」。
本期只有一部上榜时，列表位置显示「本期就这一部，已经放在页首」，不再摆一个空列表。

两个脚本共用一份规则，是因为这条链路有两个入口：周榜先生成（含列表），
生成器后生成（含大图）。规则写在各自脚本里迟早会漂，测试也盯不住。

测试：Node 集成测试新增 `the hero follows the weekly pick and can be pinned by hand`，
覆盖「默认跟榜 → 手选钉住 → 交回自动」三步；`the builder reproduces the shipped
catalogue byte for byte` 的临时站点也要拷 `data/`，否则复现不出同一页面。
`framepick-picks-smoke.py` 新增 `test_hero_and_the_list_never_show_the_same_film_twice`，
并改成按「归档全集 − 主推」算榜单、名次按真实排名断言。

## 首屏轮播（自动左右切换）

大图不是一张图，是一列幻灯片：`<article class="feature">` 变成裁剪容器，
里面 `.hero-track` 横排 `.hero-slide`，靠 `translate3d(-100% * n)` 换页。
生成器只写静态标记，切换交给 `framepick.js` 的 `initHeroCarousel()`。

**六张怎么来的**：第一张是主推（手选 > 本周推荐第一部 > 最新收录），
其余从「没进首页九张、也不在本周榜单」的作品里按收录时间顺补，最多五张，
角标写「同样值得看」。这条规则的意义是**首屏不自我重复**——
轮播里的每一部都不会在下面的榜单和栅格里再出现一次，同时片库长尾也有露脸机会。
六张一轮约 42 秒，够看完两张再翻页。片库太小时就只剩一张，这时不生成控件（没有可切换的，按钮只是噪音）。

**只往一个方向走**：末尾挂一张第一张的 **JS 副本**（`.hero-slide.is-clone`，`inert` + `aria-hidden`，
剥掉 `data-open-film` / `data-outbound-film`，只当画面）。走到副本时画面就是第一张，
下一拍先 `transition:none` 无声跳回真的第一张、强制回流后再往前走一格——
所以位置只增不减，不会像最早的版本那样从最后一张倒着把中间几张滑回来。
往回退同理：在第一张按上一张，先无声挪到副本（画面一样），再向左滑出最后一张。
副本在 JS 里克隆，静态页和无脚本访问仍然只有第一张。

**行为**：7 秒自动前进；鼠标移上去、键盘焦点落在控件里、标签页切到后台都暂停；
左右按钮、圆点、键盘左右键、手机横划都能切，手动切过之后重新计时。
`prefers-reduced-motion: reduce` 下不自动播、不做位移过渡。
非当前页整块带 `inert` + `aria-hidden`，键盘不会 tab 到看不见的链接上；
横划之后紧跟的那次 click 会被吞掉，不会顺手把详情弹窗打开。

**加载**：第一张封面 `fetchpriority="high"`（它是 LCP），其余 `loading="lazy"`，
每次切换后把下一张的 `loading` 改成 `eager` 提前拉——切过去的那一刻不该是空框。
从一张加到六张，静态 HTML 只多约 4 KB、gzip 后 0.5 KB（副本在浏览器里克隆，不进页面）。

**版式**：桌面控件压在封面左下（左下角原来是空的），`原片封面` 小字挪到右下；
手机上卡片底部被「免费原片 · 在原平台播放」占着，控件改成卡片内单独一行右对齐，
箭头放大到 32px。移动端单列时列宽写成 `minmax(0,1fr)`——
不然 `1fr` 的最小尺寸按内容算，卡片会比屏幕宽出几十像素（原来被 `overflow:hidden` 挡着看不见）。

测试：`framepick-picks-smoke.py` 的 `test_hero_carousel_rotates_by_itself_and_can_be_stepped_by_hand`
覆盖自动前进、按钮／圆点切换、`inert`、减动效不自动播，以及**单向循环**——
走到最后一张继续往前，位置只该继续往前（`translate3d(-600% → 副本)` → 再往前回到第二张），
第一张按上一张滑出的必须是最后一张；
`test_hero_and_the_list_never_show_the_same_film_twice` 加断言「轮播六张互不重复，也不和榜单撞车」；
无脚本用例断言控件不出现、第一张仍在。

## 片库每页显示多少部

`library.html` 的筛选行加了「每页」下拉：自动（手机 6 · 桌面 12）/ 12 / 24 / 48 / 全部 / 自定义…。
原来每页数量写死在 `perPage()` 里跟着屏幕断点变，手机上想一次多看点只能一直翻页。

- `state.per` 默认 `'auto'`，跟着 `matchMedia('(max-width:760px)')` 走；选了具体数字就不再理会断点，
  `matchMedia` 的 change 监听也只在 `auto` 时重置页码（否则会把读者定的视图切走）。
- 「自动」这项的文字由脚本写成「自动（12 部）」，读者不用猜自动到底是几部。
- 换每页数量一律回到第 1 页：否则 24 部一页翻到第 5 页、再切回 12 部一页就停在越界页上看空。
- 选「全部」时 `lastPage` 恒为 1，上下两条翻页条都清空，`#libCount` 也不再显示「第 x / y 页」。
- **自定义…**：选它才露出一个数字框（`#libPerCustom`），回车或失焦生效，范围 1–200。
  填超了夹到边界并把夹过的值写回框里（填 999 就该看到 200，不能留在 999 上骗人）；
  填不出数就退回原来的值。切换回预设时输入框收起。
- **一个坑**：从自定义切回预设时，数字框补上来的 blur/change 会把 `state.per` 又拽回 `custom`，
  下拉看起来「点了没用」。`applyCustom()` 开头先检查 `perSelect.value !== 'custom'` 就返回。
- 认地址参数 `?per=24`（预设直接命中；`?per=30` 这类任意数字当作自定义；坏值退回 `auto`），
  方便分享某个视图；和其它筛选一样只读不写地址，不做 localStorage 记忆。

测试：`framepick-library-smoke.py` 新增 `test_per_page_choice_keeps_the_list_and_the_pager_honest`
（24 → 翻页 → 回到第 1 页 → 12 → 全部，数量、范围文案、翻页条都跟到底）、
`test_per_page_accepts_any_number_by_hand`（自定义 30、999 夹成 200、空值回退、切回预设收起输入框）与
`test_per_page_choice_travels_in_the_url`（`?per=24` / `?per=30` 生效、`?per=bogus` 退回自动）。

## 片库翻页条：跟正文左对齐、翻页时高度不变

用户提的两件事：「收录页下方没对齐」「上方跳转不同分页时，导航栏总是在变」。

- **左对齐**：`.pager` 原来是 `justify-content:center`，正文和栅格都是左对齐起于 80px，翻页条却居中，
  看着像另一套版式。改成 `flex-start`，现在栅格和翻页条的起始 x 都是 80。
- **高度跳动**：页数一多，页码按钮个数就会变（7 个、8 个…），`flex-wrap:wrap` 一换行，
  翻页条高度从 56 涨到 58、再涨到 98，把上面的 `#libCount` 顶走一位。
  两条一起治：`pageList()` 超过 7 页时**固定返回 7 位**
  （`1 2 3 4 5 … 末` / `1 … 末-4 … 末` / `1 … 上 当 下 … 末`），
  再加 `flex-wrap:nowrap`，宽度和高度都不再随页码漂。
- **窄屏**：≤760px 页码按钮收窄成 30×32、箭头只留图标（`.pager-step span` 隐藏）；
  ≤360px 页码整排让位给一句「第 x / y 页」（`.pager-status`，插在「下一页」**之前**，
  顺序才是 `❮ 第 2 / 10 页 ❯`）。520px 起就能放下 7 位页码，所以阈值定在 360 而不是更大。

实测翻页时高度恒定：1440 → `1280×62`，760 → `724×56`，390 → `354×56`，
320／360 → 一行 `284` 宽、无横向溢出。

## 本周推荐至少五张卡（补选）

标题下是五列栅格，首名被首屏大图占掉后只剩 4 张，右边空一格——用户看到的就是「不满 5 个」。

- 规则：**标题下至少 5 张**。不够时从「本期窗口之前就已上架」的作品里按 `intakeDate` 倒序补，
  只补空缺、不改名次。窗口之后（本周才收录的）不进来——它们下周才该被评，提前塞进这一期等于插队。
- 说实话：补的卡片挂一枚「补选」小标签、日期照实写（多半早于本期），
  名次位显示「＋」而不是 06（写 06 就是在编一个不存在的位置），`aria-label` 也写「补选：查看《…》」。
- 不算进本期：补选不进归档的 `films`，单独存在 `supplement` 里；
  脚注时长仍只统计本期入选的，「末尾 1 部补选自片库，标「补选」，不是上一周首发的新作」。
- 一部都没有的周仍然留空状态。那种情况下补五部旧片才是真凑数。
- 下游要跟着让开：`build-framepick-library.mjs` 的 `thisWeekPicks()` 现在把 `films + supplement`
  一起返回，首页九张卡和首屏轮播都不会再出现同一部（否则上半页刚铺过，下半页又来一次）。

测试：`framepick-picks-smoke.py` 新增 `test_the_week_always_lists_at_least_five_cards`
（至少五张、补选卡带「补选」、日期必须早于窗口、不许出现在入选名单里、没补选时不许出现「补选」字样），
其余用例的计数口径从「归档 films − 主推」改成 `listed + supplement`，名次断言改成
`[02, 03, 04, 05] + ['＋']`。

## 结果

| 指标 | 改前 | 改后 |
|---|---|---|
| index.html | 150.4 KB | 59.0 KB（-61%） |
| gzip 后 | 27.7 KB | 15.8 KB（-43%） |
| 首页作品卡 | 55 张 | 9 张 |
| 首页区块 | 主推 + 周榜 + 完整片库 + … | 主推轮播 + 周榜 + 最近收录 9 部 |

首屏改成六张轮播后：index.html 70.1 KB、gzip 17.7 KB（多出的是五张幻灯片的文字与控件）。

## 已知取舍

- 首页不再有就地筛选，搜索会跳到 `library.html`（表单 GET，无 JS 也能用）；
