# 排版对齐、首屏画质与一次白下的流量（2026-11-09）

用户说「再进行一下优化，先不要管推送」。这轮只动本地，不发布。
先做了一遍机器审计（三种页面 × 320/390/834/1440 四个宽度），把「看着别扭」的量成数字，再按数字改。

## 1. 首屏主推那行说明被切在引号里

`firstSentence()` 只取第一个句号/问号，而句读常常落在引号里面：

```
作者 妄鱼1114 的 AI 短片，原页简介只留了两句设问：「虚神也会保护人类吗？
```

半截引号，看着像断行事故。现在切完还要检查引号是否闭合（`「」『』“”（）`），
没闭合就退到开引号之前再补省略号，得到：

```
作者 妄鱼1114 的 AI 短片，原页简介只留了两句设问…
```

截断点落在开引号之后的，同样退到引号前，不会再交出半句话。

## 2. 周榜五张卡的片名高度不一，下面几行全错开

`岁岁平安`（一行）与 `CLAUDE：好孩子，晚安`（两行）并排时，首发日期相差 33px，
理由段也跟着错位，一排看过去像没对齐。实测：

| | 片名高 | 首发行 y |
|---|---|---|
| 一行标题 | 33 | 1074 |
| 两行标题 | 67 | 1107 |

改法是给 `.pick-link h3` 留两行高度（`min-height:2.9em`），改后五张卡的标题统一 67，
行内首发行 y 只有一个值。

**没有用 `line-clamp` 裁行**：英文长片名（`Bounty Hunters: The Daring Rescue`）在 320px
两列布局下要三行，裁了就成了「Bounty Hunters: The…」。片名是内容，宁可那一张卡自己矮一截。
实测 1440 / 760 / 390 / 320 四个宽度下行内全部对齐、无横向溢出。

## 3. 首屏大图只有 640w，铺到 823px 是糊的

首屏图片的显示宽度是 823px（1440 视口下 65vw），而 `src` 只有 640w —— 放大 1.29 倍，
高分屏更明显。现在：

- `framepick-cover-build.mjs` 顺手再出一张 `-<真实宽度>w.webp`（`min(1280, 母版宽度)`，
  母版不足 900 宽就不出，抖音那批 440×330 的源本来就没有可放的细节）；
  文件名带真实宽度，`xushilu-1152w.webp` 就是 1152，不拿 1280 的名字装 1152 的图。
- 生成器在首屏 `<img>` 上写 `srcset` + 原有的 `sizes`；文件不存在就退回单张，不写死一个 404。
- `build-site.sh` 的图片改写去掉引号锚定（`srcset` 里的 `img/x-1280w.webp 1280w` 不带引号，
  锚了就漏改），产物校验也把 `srcset` 的每一档纳入，缺文件当场失败。

60 部里 42 部有母版够大的大图，其余 18 部（抖音 / YouTube 源）母版本身不到 640，不做假放大。

## 4. 顺手抓到一个更大的浪费：详情缩略图被提前下载

`toFilm()` 给详情兜底记录建 `new Image()` 时直接赋了 `src`，**一赋就发请求**。
首页主推那六部都走这条路，于是六张用不到的 640w 缩略图照下不误 —— 详情弹窗可能永远不打开。

改成把地址挂到 `data-cover`，展开详情时才由 `coverOf()` 取用。首页图片请求 19 → 13。

| 指标 | 改前 | 改后 |
|---|---|---|
| 首页图片请求 | 19 张 | 13 张 |
| 首页图片传输 | 935 KB | 663 KB |
| 首屏主图实际取用 | `xushilu-640w`（放大 1.29×） | `xushilu-1152w`（1.4× 密度） |

也就是说：**首屏更清楚的同时，整页还少下了 272 KB。**

## 5. 移动端 9–10px 的小字抬到 11px

390px 下这些字都在 9–10px：`watch-note`（免费原片 · 在原平台播放）、`filter-note`、
页脚、卡片作者行、`#resultCount`、题材标签、`feature-meta`、周榜期次。
统一抬到 11px，320 / 360 / 390 三个宽度复核无溢出、无换行错位。

## 6. 测试跟着改

- `framepick-oss-smoke.py` 的「详情优先用大图」用例原来直接拿 `img/*-1280w.webp` 全集的第一个
  当深链，exFAT 的 `._xxx` 伴生文件会混进来（`?film=._alltogether` 打不开空详情）。
  改成「剔除 `._` 且必须在 `films-data.js` 的已上架名单里」再取交集。
- Node 集成测试的「逐字节复现」用例要复现 srcset，临时站点必须知道有哪些档位，
  于是只拷 `index.html` 当前引用的那十几张封面（整目录 `cp` 会撞沙箱批量复制策略）。

全量：85 项 Python OK（19 项影院形态跳过），4 个 Node 套件 52 项全过。

## 7. 第四轮：字号下限、按钮错位、半个词

前三轮扫的是 320–1440 的溢出与错位；这一轮换了两个角度。

**桌面端字号比移动端还小。** 前几轮为了小屏可读，把移动端的 9–10px 统一抬到 11px，
桌面侧没动，于是出现倒挂：`1440` 下 `.image-note`、`.watch-note`、`.pick-release`、
`.search-hint`、`.filter-note` 这些还是 10px，而 `390` 下它们是 11px。两个 CSS 里的
19 处 `font-size:10px` 全部改成 11px，`tiny`（<11px）在四个宽度下归零。

**账号弹窗按钮错位 4px。** `.membership-dialog .button { margin-top:8px }` 这条是想给
会员卡里的单按钮留呼吸，但 `.account-actions` 里的提交按钮同样命中，被压低 8px、
容器高度变成 `8 + 44`。测得按钮中心 569.2、旁边「还没有账号？注册」中心 565.2。
加 `.account-actions .button { margin-top:0 }` 后两者都是 565.2，并给 `#accountSubmit`
112px 最小宽度，让它像主行动而不是一个窄条。

**首屏箭头 28px，小于移动端的 32px。** 桌面调到 34×34、图标 16px，移动端同步 34。
顺带用 `closest('a')` 与 `elementFromPoint` 确认箭头和圆点是 `.hero-controls` 的兄弟
节点、不在 `<a class="feature-media">` 内部，审计报的「重叠」是刻意的覆盖式控件。

**周榜理由切在半个词上。** `reasonOf()` 在 54 字内找不到逗号顿号时直接硬切，
得到 `…最佳短片动画奖及多项国际 AI 电…`。改成三级退让：句读（，、；：）优先且门槛
从 30 降到 24，其次退到最近的空格，最后才硬切，收尾再清掉悬空标点。
现在收在 `…画面克制而有分量…`。

`me.html` 之前一直是空状态壳，用 localStorage 注入 8 条观看记录后才露出真实布局
（含超长片名），四个宽度干净。

复核：周榜五卡首发日期在 1440/1000/834 上 `spread = 0`，760/390/320 两列组内对齐；
`run-tests.sh` 85 项 Python OK（19 跳过）+ Node 各套件 `fail 0`；`build-site.sh`
产物 245 文件、陈旧清理 0。CSS 版本号 `20261109-type9`。

## 8. 第五轮：从「暗色模板」改成编辑型暗刊

用户反馈「界面还是不是很高级」。机器审计已经查不出问题了，这一轮换成设计批评：
把三页整页截图逐块看，找出「廉价」的具体信号，而不是继续修像素。

**诊断**：页面靠 1px 线框划分所有层级（`--line` 还是偏亮的 `#30333a`，
用在卡片动作行、标签边框、tab 底线、搜索框、分页器、会员卡）；首屏 CTA 是一整块
纯白实心按钮；金色同时在分类、评分、日期、下划线、焦点、收藏等八处出现；
圆角有 2/3/4/5/6/8/9/10px 八种；一张卡上叠了角标、题材、时长、状态、评分、
「站内评分 · 暂无评分」、片名、作者、来源、描述、三个动作共 11 个元素。

**改法（减法为主）**：

1. **重建设计变量**：三层明度 `--bg:#0a0b0d / --surface:#141619 / --raised:#1b1e23`；
   文字三档改成暖白标题、暖灰正文、冷灰标签；线分两级且都压暗；金色降饱和到
   `#c9a97a`；全站圆角收敛成 `--r:2px` / `--r-lg:3px`（圆形与胶囊除外）。
   对比度复验：三页全部达到 WCAG AA。
2. **去掉白底实心 CTA**：`.feature .watch` 改细描边 + 字距，hover 才整体反转；
   详情弹窗的「前往原平台观看」同步改描边，白底实心只留给表单提交。
3. **少用线**：卡片动作行顶线、收藏按钮边框、连载状态小方盒、会员卡边框、
   搜索框外框全部移除；搜索改成一条底线并与 tab 底线同色；分页器从一排小方盒
   改成「数字 + 当前页下划线」；分类选中态由品牌红改亮白线。
4. **卡片减法**：删掉每张卡重复的「原片封面」图注；隐藏与「待评」重复的
   `.community-score`（注释里写明将来开评分要恢复）；`data-completion="standalone"`
   的「单部」不再显示；`data-access="free"` 的「免费精选」角标只在非免费时贴，
   所以给 `framepick-library-page.js` 的卡片补了 `data-access`；顶行从
   `space-between` 改成「题材 · 时长」成组靠左、评分靠右。
   角标和首屏「本周主推」都改成压在图上、去底去框、靠字距和投影站住。
5. **节奏**：栏目标签加 `.16em` 字距；区块间距 90 → 120px，让「章」之间有呼吸；
   「选片标准」左列末段推到底部与右列呼应；「关于」正文 11px → 12.5px。
6. **一致性**：hero 作者与时长从两行 grid 并成一行「妄鱼1114 · 10:17」；
   详情弹窗封面下方的模糊垫底由亮橙色雾压成很暗的底纹；
   页头三页补齐「我的记录」并去掉重复的第二道竖线；「我的」改名「我的记录」，
   避免与「我的收藏」并排读成重复项。
